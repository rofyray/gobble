Every dish gets an owner

Building Gobble, a Thanksgiving potluck agent that keeps the list in your group chat and asks the right person about every gap.

By Rofy · November 2026 · github.com/rofyray/gobble

The problem

A potluck plan usually lives in a group chat. People reply with what they're bringing and the thread scrolls on. Nobody keeps the list. You find out on the day that there are three pies and no gravy, that two people made mashed potatoes, that a dish needs the oven during the four hours the turkey is in it, or that the only dessert has nuts and one guest can't eat them.

The fix people reach for is a spreadsheet, and nobody fills in a spreadsheet. I wanted the list to keep itself while everyone kept talking the way they already do.

What Gobble does

Gobble is an agent that sits in the chat room. The host posts the basics once. After that, guests just talk, and Gobble records each claim and checks the plan against the headcount, diets, allergies and oven time. When something is missing, doubled or unsafe, it asks one person about that one thing.

Here's a stretch of the run in the video:

kiapecan pie from me! and I can do mashed potatoes
ceeheads up, tree nut allergy here. I'll grab drinks
gobbleDrinks are yours, @cee, and that's noted. Heads up: there's a tree-nut allergy at the table, and the pecan pie has tree nuts. @kia, can you label it and keep it on its own plate?
kundamine's pumpkin pie, no nuts. I'll do mashed potatoes too
gobblePumpkin pie is yours, @kunda, so there's a nut-free dessert on the table. @kia and @kunda both have mashed potatoes. @kunda, want to switch to a green veg? Nobody's on it yet.

Cee says they have the allergy, and Gobble records it, but the warning it posts never names them. The board shows the table's allergies as counts with no names attached. When every dish has an owner, Gobble posts the final list and asks the host whether to lock the plan.

Then Gobble hands off to Sous-chef, a second agent in the same room. Sous-chef answers kitchen questions for whoever asks: a recipe scaled to what you signed up for, or a shopping list. It can read the plan but can't change it.

The model talks, the engine counts

The design decision that mattered most: the language model never does arithmetic.

Gobble is a Claude Code session. Its brief is a CLAUDE.md file in its working folder, and it has one tool that matters, a small CLI called ./gobble. When kia says "pecan pie from me", Gobble runs something like this:

./gobble claim kia dessert --item "Pecan pie" --tags contains-tree-nuts

The CLI writes the claim and runs a deterministic reconciliation engine over the whole plan. The engine knows that a pie serves about 8, that 15 guests need about 15 servings of dessert, that the turkey occupies the oven from 11:30 to 3:30 for a 4:00 dinner, and which dishes carry which allergens. It returns a list of gaps in priority order: unclaimed dishes, shortfalls, doubles, uncovered diets, allergen conflicts and oven clashes. Gobble's job is to read that list and ask about the top item in plain words.

So when Gobble says "we're about 7 servings short for 15 people", that number came from code with unit tests, and the model only had to phrase the question. The same plan feeds a live board on Vercel, styled as a kitchen ticket rail, which polls every few seconds while the chat runs.

Why split it this way

An agent that is wrong about the gravy once loses the room. Counting servings, timing an oven and matching allergens are problems with right answers, so they live in code. Reading "oh true, I'll bake it at home and bring it hot" and knowing that means "set oven time to zero" is a language problem, so it lives in the model.

Where Switch fits

Switch is what puts an agent into a real group chat with real people. Gobble wouldn't have a room or any routing without it. Four Switch features carry the project:

  • A room template. One YAML file in the repo creates the room, both agents, their instructions and a kickoff message. Setting up a fresh room for the demo took about a minute.
  • !assign-agent @gobble. Every message without an @mention goes to Gobble. Guests never type a command or tag a bot, which is the whole point for a group of relatives.
  • Two agents in one room. Gobble hands off to Sous-chef with an ordinary @mention, and both see the same conversation.
  • Claude Code as the runtime. Each agent runs in its own folder in the repo and picks up its own CLAUDE.md, so the full prompt is versioned in git and the Switch instructions field is a one-line pointer to it.

The room in the demo runs on the Mattermost server that Switch Console sets up locally.

What tripped me up

Most of the hard parts were in setup.

Renaming a chat account. I renamed my Mattermost user from user to rofy partway through. Mattermost picked up the new name right away, but Gobble kept calling me @user and the plan was titled "Thanksgiving at User's". Switch saves the username it first sees for each person and, by design, never replaces one name with another. Fixing it took a database update and a restart of Switch's local server, and the rename also unlinked my account in Switch Console until I linked it again. If you're setting up a demo, pick your chat username before you send the first message.

Template inputs. The template's $first default for the chat app didn't resolve on my server, and the directory input re-filled itself on every keystroke. The template in the repo now names Mattermost directly and uses a plain text field for the folder.

Progress messages in the chat. Switch posts status lines like "Worked for 11s. 2 tool calls." into the room while an agent works. They help while testing. I couldn't find a setting to hide them for a demo.

Try it

The code, the room template and setup steps are on GitHub. You'll need Node 22, pnpm, Docker, Switch Console and Claude Code. The CLI and board also run without any agent, so you can drive a plan by hand:

cd agents/gobble
./gobble init --title "Thanksgiving at Rofy's" --date 2026-11-26 --dinner 16:00 --headcount 15 --host rofy --pretty
./gobble claim kia dessert --item "Pecan pie" --tags contains-tree-nuts
./gobble status --pretty

Or look at a finished plan on the live demo board.
